# ResNet-50 baseline (resnet50_v2)

> **Note (2026-10-28).** The device class `lookalike` was renamed **`ambiguous`** (same images, same labels; old events/results are mapped on read via `server/schema.json` `value_aliases`). Tables below keep the name used when they were generated; read `lookalike` as `ambiguous`. The numbers stay valid and were not rerun.
>
> **Leakage audit (scripts/check_leakage.py, data/MANIFEST.md).** `splits_v2.csv` had one leak: a single Flickr photographer appearing under two account IDs (NSID and path alias), 6 images, 1 in val and 5 in train. It did not touch test, and no near-duplicate pair crossed splits (sha256, pHash, SigLIP2 cosine), so the test numbers here are not inflated by duplicates; at most model selection on val saw one same-photographer image. New work uses `data/splits_v3.csv` via `data/manifest_v2.csv` (grouped by uploader + creator name + near-duplicate clusters), so later numbers are not directly comparable to these. The zero-shot batch prior-centering (CALIB) was off (0) for these runs, and it only applies to sets of >= 200 images anyway, so it never touched the 65-image test set; the batch-dependent path has now been removed from the eval code.

## Caveats

- The test set is small, so the bootstrap intervals are wide; rare classes (lookalike, other_aid) have only a handful of test images and their per-class F1 can swing a lot with one prediction.
- Seed spread only reflects training randomness on one fixed split, not split-to-split variance.
- Splits are grouped by Flickr uploader/creator; one uploader contributes a large share of images and sits entirely in one split.
- Most labels are single-annotator; see `results/splits_v2_summary.json` for label resolution counts.
